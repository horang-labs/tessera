## Findings that constrain implementation

1. **No existing safe automatic send primitive.** UI-level permission blocking cannot protect server-driven sends. Add conditional admission at the TerminalManager boundary and cover every competing input/attach route. Reading a snapshot then calling prompt creates a race.
2. **Turn end is not task success.** StopFailure, interruption, missing hooks, subagents, and runtime shutdown are distinct. Wake-ups remain explicit, bounded continuation requests. Do not mark a Task done or close an issue from these signals.
3. **No exactly-once PTY delivery claim.** A crash can happen after paste/Enter but before DB acknowledgement. Durable run IDs solve scheduler duplicates, not external side effects. Ambiguous attempts require an explicit unknown outcome and no automatic resend.
4. **Fresh creation differs from continuation.** Initial prompts belong to fresh launches. Recovered Sessions resume without initial prompt; follow-ups require a new proven boundary. Keep created Session identity and run identity together before launch.
5. **Owner/context must be explicit.** Session table itself is not tenant isolation. First version should restrict Automation to the configured runtime owner, record that identity, reject other users, and suspend if owner/environment changes. Do not silently pick the first user at dispatch.
6. **Provider capability is narrower than GUI settings.** Detached PTY path supports Claude/Codex selection, not arbitrary permission overrides or OpenCode model/effort. Advertise the precise supported subset, reject unsupported fields, and leave provider-native approvals intact.
7. **Runtime observation is partial.** Hook transports can fail open and expose no universal durable turn identifier. A conservative adapter must decline uncertain wake-ups; output silence, elapsed time, and transcript prose are not substitutes.

## Uncertainties carried to the orchestrator

- Sibling competitor research is pending. No comparative claim or upstream product behavior is included.
- Need packaged Windows/WSL evidence that accepted lead completion, permission blocking, semantic paste/Enter, and saved launch selection work for each enabled provider/version. Source alone cannot certify these.
- Need an input-presence/admission design that covers normal panel, Peek, popout, disconnected drafts, and raw Control keys. The architecture specifies a conservative background-only v1; richer foreground behavior is a separate decision.
- Duplicate/delayed hooks lack a universal provider event ID. A runtime epoch plus server turn sequence is a dedup aid, not proof against every delayed message; ambiguous sequences must suspend.
- Local Control's single-user model and shared Session rows do not establish multi-user Session ACLs. Supporting multiple independent Automation owners requires a separate resource-ownership design.
- Power-loss durability depends on SQLite sync policy and storage. Current synchronous=NORMAL is not a claim that an acknowledged automation dispatch marker survives power failure; implementation must resolve this before enabling automatic delivery.
