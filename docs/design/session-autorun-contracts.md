## Compatibility and final alias ownership

R0 leaves `AutomationInput`, `Automation`, `ControlResult`, `ControlResponse`, `automationInputSchema` and `validateAutomationInput` in `contracts.ts` as v1. Existing authenticated create/edit HTTP rejects Autorun with 400 `INVALID_AUTOMATION`; the new decoder/validator is not installed there. v2 bodies carry `version:2` and discriminating `mode`. v1 request/DTO decoding is structural and preserves inherited nullable worker selections; temporal/launch admission is separate. v2 validation is configuration validation only, not authority to arm or call a model.

**R2/#533 alone owns final compatibility wiring:** after implementing real Autorun persistence, engine, gate and handlers, transition those six legacy aliases/schema-validator entry points to the versioned union as needed; update owned service/repository/runtime/HTTP consumers to branch on `mode` before reading `prompt`; decode legacy rows/requests and install text-free v2 list projections and run `decisionId` linkage. No prompt sentinel or premature request acceptance. Preserve unchanged Heartbeat/Schedule validation, anchors, delivery and saved selections. R2 can change these specific shared contract aliases; other frozen shapes require an orchestrator-routed amendment. Prefer explicit versioned imports when no alias transition is needed.

R1/#532 installs only the optional provider capability; R3/#534 consumes versioned exports (including `AppNotificationV2`) and owns client notification handlers/store/UI. R3 must not independently widen legacy request/DTO aliases. `runtime-bridge.ts` stays unchanged. Server authorization, target existence and configured owner checks belong to R2; schema validity never proves them.

Client objective inputs are only `{kind:'explicit',text}` or `{kind:'preview',previewId,goalRevision}`. No client source/provenance fields are accepted. R2 rebuilds/verifies preview references and assigns persisted `verified-human` sources or explicit-author origin; criteria receive a persisted `criterionOrigin`. Packet limits also apply after materializing a preview. Criterion IDs are unique/nonempty. Objective override never cures unsafe/malformed completed context.

Preview readiness is `completed` (fresh boundary + complete-latest coverage), `running` (accepted instrumented turn + native submission, no completed snapshot required), `idle` (consumed/no accepted turn: human ownership and new submission first), or `unavailable` (reasoned context/runtime/capability failure). Missing objective is represented separately by `objective:null`. Options are current R1 attestations, not static proof constants; recommended selection must occur in those options and be non-fast. R2 rebuilds/revalidates all prerequisites at Start/Resume/replacement. Conflicting human corrections must be resolved by explicit override, never silently dropped.

Decision attention uses `kind:'decision'`, nonempty `decisionId`, attributed outcome; pre-decision pause/error uses `kind:'rule'`, `decisionId:null`, persisted reason and rule/revision identity. Dedup is exactly `autorun:<decisionId>:<outcome>` or `autorun:<automationId>:<revision>:<reason>`. R2 persists owner-only summary before sending the text-free event, and exposes latest attention in owner detail. List projections include identity only, never goal/packet/proposal/explanation text. R3 keeps native approval notifications as a separate family and handles active Sessions/reconnect/dismissal without rearming.

## Latest parent coordination and exact R1 → R2 handoff

The [large-history/legacy-reason clarification](https://github.com/horang-labs/tessera/issues/531#issuecomment-5957420337) and [first-running producer clarification](https://github.com/horang-labs/tessera/issues/531#issuecomment-5957459209) are included in this freeze. Absolute `startByte/endByte/latestTurnStartByte` have safe-integer bounds independent of file size. `contextSourceSchema` separately records ordered nonoverlapping `scannedRanges`, measured `bytesScanned` (including rereads), and measured `maxRecordBytes`; at most 32 MiB may actually be scanned and any native record is at most 2 MiB. Range lengths cannot exceed actual measured reads. All supplied item ranges and the entire latest-turn interval through durable cutoff must be covered by the scanned ranges. A small identity header plus a 500-byte tail beginning at 40 MiB is valid with 628 measured bytes; an uncovered latest turn or over-budget read is rejected. R1 proves identity, latest-turn completeness and independent human goal provenance rather than reading the whole large transcript or guessing omitted content. Legacy `explicit-stop`/`acknowledged-no-retry` are accepted in shared summary/detail fixtures.

Additional exact exports in `autorun-contracts.ts`: `autorunHookEvidenceSchema`, `AutorunHookEvidence`, `autorunTurnEvidenceSchema`, `AutorunTurnEvidence`, `autorunGoalEvidenceSchema`, `AutorunGoalEvidence`, `autorunEvidenceResultSchema`, `AutorunEvidenceResult`. R1's concrete producer is **`CliProvider.autorun.readAutorunEvidence(request: AutorunEvidenceRequest): Promise<AutorunEvidenceResult>`**, with required owner/environment/Session/provider-conversation/input epoch/saved worker selection, current gate-captured turn evidence, goal revision, previous human source IDs and AbortSignal. It returns verified-human objective provenance and newly verified corrections, or explicit missing/conflicting objective evidence, plus current native submission evidence; provider/read failure is typed unavailable. No completed snapshot or model call is required to return a safely accepted first-running turn. R2 alone applies explicit user overrides, criterion defaults/overrides and its preview capability/admission checks. This seam is new; ordinary `terminal-session-history` replay exports do not supply attested evidence.

The concrete hook seam is **`AutorunRuntimePort.recordHookEvidence(event: AutorunHookEvidence)`** and **`readTurnEvidence({userId,agentEnvironment,sessionId}): AutorunTurnEvidence`**. R1's authenticated hook receiver imports types from `autorun-contracts.ts`, resolves authenticated owner + observed terminal binding, and publishes through the existing **`getAutomationRuntime()?.autorun?.recordHookEvidence(...)`** (`src/lib/automation/runtime-bridge.ts`, unchanged registry). R2 implements the synchronous gate store/check/read, rejects foreign/stale/wrong provider-generation identities and deduplicates native observer IDs. Missing optional capability is unavailable, never a fake receipt. A stored hook does not independently become a Boundary; existing qualified runtime completion and child/approval/input gates still decide that. `running` contains accepted runtime identity + `ProviderTurnSubmission`; `completed` contains qualified Boundary + `ProviderTurnCorrelation`; idle/unavailable cannot arm. R2 captures this association under the gate, passes it to R1, then rechecks epoch/runtime/binding after async reads and in final synchronous arm/CAS. Provider completion context remains `readAnalysisContext`, used only after qualified completion.

Claude completion correlation additionally carries `stopTextHash` (SHA-256 of the exact UTF-8 Stop final text); submission evidence omits it and `completionHookId`. R1 can compare native final text without retaining raw Stop text in the cross-owner handoff. Hash equality alone never qualifies completion: exact native prompt ID, submit cursor, unique durable lineage/final UUID/end byte and clear runtime gates remain mandatory. Codex retains the native turn ID and matched lifecycle records. This server-only authenticated hook contract is separate from renderer attention WS.

## Owned analysis recovery — authorized #532 amendment

`session-types.ts` adds `SupervisorSettlementObservationRequest = { version:1; userId:string; agentEnvironment:'native'|'wsl'; invocationId:string }` and optional `AutorunProviderPort.observeSupervisorSettlement(request): Promise<SupervisorSettlementObservation>`. Port version remains 1; older providers remain compatible, and absence is unknown/quarantined. `autorun-contracts.ts` exports `supervisorSettlementObservationSchema` and `SupervisorSettlementObservation`.

The result always echoes `{version:1,userId,agentEnvironment,invocationId,observedAt}`. It is either `{kind:'quiescent',code:'SUPERVISOR_QUIESCENT',proof:{kind:'owned-invocation-closed',launchId,closedAt,settledAt}}` or `{kind:'unknown',code:'SUPERVISOR_PROCESS_UNCERTAIN',reason:'missing'|'identity-mismatch'|'active'|'incomplete'|'unsupported'}`. Successful proof means that the exact durable prelaunch authorization is closed and every owned launch has affirmative settled/quiescent evidence. Missing/ambiguous evidence, PID absence or reuse never qualifies. The adapter checks its own provider identity as well as explicit owner/environment/invocation identity.

R1 persists ownership before launching any invocation process, preserves restart-readable receipts, and queries/reconciles only that invocation. Observation starts no inference, returns no output/decision, and kills no process. R2 validates the echoed identity, consumes quiescence idempotently only to release that invocation's capacity quarantine, and never replays output, resets counts or automatically re-arms the same boundary. Unknown/alive retains capacity quarantine. With zero worker writes, ordinary Pause/drain may return manual worker input independently; unknown actual worker writes preserve the existing recovery hold. Explicit re-arm still requires a fresh accepted turn and all normal readiness checks. This implements #529's interim finalization decision without adding synchronous filesystem I/O inside the admission gate.
