## Compatibility and final alias ownership

R0 leaves `AutomationInput`, `Automation`, `ControlResult`, `ControlResponse`, `automationInputSchema` and `validateAutomationInput` in `contracts.ts` as v1. Existing authenticated create/edit HTTP rejects Autorun with 400 `INVALID_AUTOMATION`; the new decoder/validator is not installed there. v2 bodies carry `version:2` and discriminating `mode`. v1 request/DTO decoding is structural and preserves inherited nullable worker selections; temporal/launch admission is separate. v2 validation is configuration validation only, not authority to arm or call a model.

**R2/#533 alone owns final compatibility wiring:** after implementing real Autorun persistence, engine, gate and handlers, transition those six legacy aliases/schema-validator entry points to the versioned union as needed; update owned service/repository/runtime/HTTP consumers to branch on `mode` before reading `prompt`; decode legacy rows/requests and install text-free v2 list projections and run `decisionId` linkage. No prompt sentinel or premature request acceptance. Preserve unchanged Heartbeat/Schedule validation, anchors, delivery and saved selections. R2 can change these specific shared contract aliases; other frozen shapes require an orchestrator-routed amendment. Prefer explicit versioned imports when no alias transition is needed.

R1/#532 installs only the optional provider capability; R3/#534 consumes versioned exports (including `AppNotificationV2`) and owns client notification handlers/store/UI. R3 must not independently widen legacy request/DTO aliases. `runtime-bridge.ts` stays unchanged. Server authorization, target existence and configured owner checks belong to R2; schema validity never proves them.

Client objective inputs are only `{kind:'explicit',text}` or `{kind:'preview',previewId,goalRevision}`. No client source/provenance fields are accepted. R2 rebuilds/verifies preview references and assigns persisted `verified-human` sources or explicit-author origin; criteria receive a persisted `criterionOrigin`. Packet limits also apply after materializing a preview. Criterion IDs are unique/nonempty. Objective override never cures unsafe/malformed completed context.

Preview readiness is `completed` (fresh boundary + complete-latest coverage), `running` (accepted instrumented turn + native submission, no completed snapshot required), `idle` (consumed/no accepted turn: human ownership and new submission first), or `unavailable` (reasoned context/runtime/capability failure). Missing objective is represented separately by `objective:null`. Options are current R1 attestations, not static proof constants; recommended selection must occur in those options and be non-fast. R2 rebuilds/revalidates all prerequisites at Start/Resume/replacement. Conflicting human corrections must be resolved by explicit override, never silently dropped.

Decision attention uses `kind:'decision'`, nonempty `decisionId`, attributed outcome; pre-decision pause/error uses `kind:'rule'`, `decisionId:null`, persisted reason and rule/revision identity. Dedup is exactly `autorun:<decisionId>:<outcome>` or `autorun:<automationId>:<revision>:<reason>`. R2 persists owner-only summary before sending the text-free event, and exposes latest attention in owner detail. List projections include identity only, never goal/packet/proposal/explanation text. R3 keeps native approval notifications as a separate family and handles active Sessions/reconnect/dismissal without rearming.
