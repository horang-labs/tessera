# Install skills only in the agent environment

After explicit user action, Tessera runs the standard Skills CLI exclusively in the current Project's `agentEnvironment`; its interactive picker owns the exact provider target set for that run. Installation state is user-global within that agent environment rather than project-specific, so Projects that share the same provider homes share one state; changing to another `agentEnvironment` neither duplicates the skill into the new environment nor removes the previous environment's installation. A Windows backend with a WSL agent runs setup, discovery, update, and Tessera-specific removal only in the WSL login environment, while a native agent runs them only natively. Tessera never falls back to the opposite environment or installs on both sides, and if it cannot connect to and validate the target environment it performs no mutation and reports exact recovery guidance. Tessera application removal is the separate cross-lifecycle case defined by ADR 0011: it covers known Tessera-owned installations in each installation's owning environment.
