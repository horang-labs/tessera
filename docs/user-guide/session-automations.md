# Session automations

Choose **Continue this work** from a Claude Code or Codex PTY Session, in the normal panel or Kanban Session Peek. Autorun is selected initially; it stays off until you confirm **Start continuation**. Choose **Repeat a message · Heartbeat** in the same setup to send fixed text instead. **Schedule a Session** in a Worktree opens the same manager for future new Sessions. Saved rules retain their original method and history.

Autorun uses a separate supervisor to review the worker's actual conversation and choose a fresh next instruction, judge the objective complete, or ask for your attention. It keeps the same worker. Review the verified human objective and corrections, or explicitly set your own objective. Constraints and completion criteria are optional. The default criterion is labelled **Judge against the saved objective**. The supervisor selection is independent of the worker and must be currently supported and proven available. Opening setup and previewing the conversation do not invoke a model.

A fresh completed turn or a safely instrumented running turn can be armed. A running turn shows **Waiting for worker · Reviews after this turn ends**. If an earlier boundary was already consumed, send a new instruction normally before resuming. An explicit objective cannot repair missing or malformed latest context. **Check again** refreshes the preview without running the supervisor.

Advanced settings show supervisor selection, delay, expiry and finite instruction/analysis limits. New Autorun defaults are two minutes after completion, ten instruction attempts, twenty analysis attempts, an eight-hour lifetime and a 120-second analysis timeout. Each supervisor call or retry consumes an analysis attempt; instruction attempts include failures and unknown delivery. Supervisor calls use your existing provider allowance. **Save for later** retains a configuration for later instead of taking input ownership now.

Heartbeat sends your fixed message after a confirmed turn and the saved delay. It does not judge goal completion or invoke a supervisor. Its default lifetime is eight hours and ten attempts. Existing saved launch settings, including inherited worker settings, remain unchanged.

Arming grants automation exclusive input control. Watching, scrolling and copying stay available; local chat drafts remain intact. **Pause to type** stops new automation and remains accessible for enabled automations or actual held input, including analysis, approvals, errors and draining after deletion. An ended rule with human input already available does not offer Pause. It does not stop the worker. A 202 response means an earlier input transaction is draining; typing remains locked until authoritative human ownership returns. Native approvals still require your response in the worker Session. Delete requires confirmation, retains the Session and history, and never bypasses draining or uncertain delivery.

Session continuation Resume opens a new readiness preview with verified human corrections and remaining lifetime counts. Editing first pauses and waits for input release. Saving an edit leaves it disabled; explicitly Resume after reviewing it. Changing the saved method requires pause/drain and a confirmed replacement with the displayed new limits; old history remains inspectable. A consumed boundary cannot be revived by replacement. **Limit reached** or **Expired** offers **Review limits and expiry** to edit the saved limits; lifetime instruction and analysis counts stay intact. Saving leaves the rule disabled, then **Resume** explicitly enables it. Schedule Resume uses its saved schedule and does not require a worker turn boundary.

Overview separates automation state, analysis, supervisor judgment and delivery. History groups decisions with linked delivery status and exposes rationale, criteria, cited excerpts and full/bounded/compacted/incomplete coverage. **Goal judged complete** is attributed to the supervisor; it does not archive the Session, close its Task or change the board status. A proposal is not a delivery receipt. Attention and completion use distinct notification types, including for visible Sessions; dismissing or reading them does not Resume. Open an attention item to review the automation detail, then use **Back to Session** for ordinary navigation.

Schedule requires a work prompt, new Session title, future local date/time and an explicit supported worker selection. Catalog defaults prefill supported model settings; unresolved values require a choice. Once allows one attempt; a fixed elapsed interval allows up to one hundred attempts. Scheduling defaults to a thirty-day expiry. Times are stored as UTC instants and displayed with local timezone information. Schedule never automatically enables Autorun on a created Session. Its history links the resulting Session and distinguishes initial delivery from the worker turn ending.

Tessera must be running locally. Restarted interval schedules coalesce missed slots rather than sending a backlog; overdue Once has a bounded execution window. Automation-created active turns in the same Worktree can defer later scheduled creation. Independent human Sessions are not globally blocked or isolated by this feature. Saved launch choices cannot attest native TUI setting changes.

Analysis-only settlement uncertainty pauses supervision; manual worker input can still be available. Supervisor capacity remains reserved until exact evidence confirms the original analysis call has settled. Actual unknown worker delivery retains the input hold and needs inspection and explicit manual acknowledgement without retry. Partial input is not resent or discarded. Refresh after revision conflicts; a failed create retains its idempotency key when retrying the same draft. OpenCode continuation, cloud/OS alarms, calendar recurrence, Run Now and automatic approvals remain outside this version.
